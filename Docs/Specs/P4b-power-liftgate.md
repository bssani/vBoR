## 1. 왜 만드는가

- 04·06은 버튼식 전동 리프트게이트다(U-09). 05에서 박스를 여러 개 싣고(P1b), 06에서 박스가 튀어나와 있으면 닫히지 않아야 한다(계획서 §4 06 "간섭 시 미완료").

## 2. 범위

### 만들 것

1. **명령으로 움직이는 판 부모**(D1–D5, D9). 열림 각도·각속도(또는 시간)·대기 시간·소리·반복 간격은 프로퍼티(근사 자리값).
2. **버튼 연결**(D6): 판이 열기·닫기 버튼 둘을 만들거나 연결받는다(구현자가 정함). 자식 Blueprint에서 메시·버튼 자리만 바꿔 쓸 수 있어야 한다.
3. **키보드**(D7).
4. **P1 시험대**(D8): 트렁크 근사에 게이트를 붙이고, 판넬·로그에 게이트 상태·끼임 횟수를 더한다. `R`(재배치)·`B`(초기화)에서 게이트를 시작 상태로 돌린다.
5. **자동화 시험** — §4 전부.

### 범위 밖 — 하지 말 것

| 하지 말 것 | 이유 |
|---|---|
| 손으로 게이트를 밀거나 잡기 | INT-011: 버튼으로만 여닫음 |
| 대기·움직이는 중 멈추기·반대로 돌리기 입력 | D3(사용자 결정: 무시) |
| P3 흐름 04·06 단계 규칙 연결, P3 근사 차에 트렁크 만들기 | P4 골격·통합 때 |
| 실제 열림 각도·속도·소리 값 정하기 | 데이터 없음. 근사 자리값 |
| 손·몸 끼임 감지 | 손에 물리가 없다. 박스만 본다 |
| 레벨 저장 | C++만 |

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- 기존 `vBoR.*`(P1 박스 시험 포함)이 통과한다. 박스의 잡기·이동·막힘·낙하 규칙은 그대로다.
- 게이트는 박스를 관통하거나 밀지 않는다.
- 버튼 포인터 이벤트 안에서 SDK 상태를 바꾸지 않는다.
- 차 원점 피벗 보정(Actor 원점 = 차 원점)을 지킨다.
- 근사 형상임을 드러낸다(이름·주석·판넬).

## 5. 구현자가 정할 것

- 클래스·함수·이벤트·프로퍼티 이름, 상태 열거형
- 각속도와 걸리는 시간 중 무엇을 프로퍼티로 둘지, 기본값(근사 — 예: 열림 85°, 4 s)
- 끼임 판정 방법(스윕·겹침), 판 충돌 설정
- 키보드 기본 키, 경고음 반복 간격
- 버튼을 판이 만들지, 레벨에서 연결받을지

## 6. 완료 조건

1. §2의 1–5가 들어 있다.
2. §4 시험이 모두 자동화로 통과한다. 기존 `vBoR.*`도 통과한다.
3. non-unity(`-Module=vBoR`)·unity 빌드에서 vBoR 경고·오류 0.
4. AGENTS.md 보고 ①–⑤를 커밋 본문과 `HANDOFF.md`에 남긴다.
5. 시험 상태는 `not-tested`다.

## 7. 로컬에서 확인할 것 — 사용자

### Quest 3 (Link, VR Preview, `L_P1_GolfBag`)
1. 닫힌 게이트의 열기 버튼을 누른다. 경고음이 나며 1초 뒤 올라가는지, 올라가는 동안에도 소리가 나는지 본다.
2. 올라가는 중에 버튼을 눌러 본다. 무시되어야 한다.
3. 박스를 넣고 닫기 버튼을 누른다. 닫히는지 본다.
4. 박스를 입구에 걸쳐 두고 닫기 버튼을 누른다. 닿기 전에 멈추고 다시 올라가는지 본다.
5. 키보드 열기·닫기 키로 같은 동작을 한다.
6. 버튼 자리·크기, 열림 각도·속도가 자연스러운지 본다(근사).
