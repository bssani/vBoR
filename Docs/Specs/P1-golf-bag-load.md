## 0. 결정

|---|---|---|

| D6 | **두 손 잡기**(U-08, 2026-10-10 사용자) | 한 손으로 잡은 채 다른 손으로도 잡으면 두 손 모드다. 방향은 두 잡은 점의 위치로 정한다: 한 손을 멈추고 다른 손만 움직이면 멈춘 손 쪽 잡은 점은 그 손에 붙어 있고 움직인 쪽만 돈다. Yaw는 따르고 기울기는 한도(45°) 안, 크기는 그대로. 자세한 규칙은 §2 |

## 1. 왜 만드는가

계획서 §5: 사용자가 가장 우려한 항목이다. 대표 골프백 하나, 시작 자세 하나, 적재 위치 하나로 아래를 **각각** 확인한다.

- **정적 적합성:** 목표 위치에 겹침 없이 들어가는가.
- **삽입 경로:** 트렁크 입구에서 목표 위치까지 차체를 뚫지 않고 옮길 수 있는가.
- **잡기·놓기가 반복해서 되는가.** 손바닥 잡기 인식이 맨손 허공에서 안정적인가(P0-b는 poke만 봤다).
- **추적 손실 처리:** 잡은 채 손이 시야 밖으로 나가거나 가려질 때 골프백이 튀거나 던져지지 않는가(AGENTS.md "손 추적 손실은 보류이지 완료가 아니다"). ISDK 잡기는 추적 신뢰도를 보지 않는다(조사 기록 2026-10 §2 함정 2).

> ⚠️ 이 실험의 성공을 실차 적재성(무게·힘·마찰)으로 서술하지 않는다(AGENTS.md "하지 말 것").

## 2. 범위

### 만들 것

**다시 쓰는 부품** — `Source/vBoR/Interaction/` (ISDK·MetaXR에만 의존)

1. **손 리그 Pawn에 잡기 허용 옵션** (`AVBoRHandRigPawn`)
   - "잡기 허용" 프로퍼티(기본 **꺼짐** — P0-b 시험대는 그대로 poke만). 켜면 잡기 리그를 활성화하고 **손바닥 잡기만** 쓴다.
   - P0-b R2-1의 원거리·레이 잡기 차단(`SetGrabDetectionTypeAllowed(DistanceGrab/RayGrab, false)`)은 잡기를 켜도 유지된다.
2. **들어 옮기는 물체 부모** (`AVBoRCarryObject`, `Blueprintable`)
   - 메시(교체 대상)와 충돌 형상. 자식이 메시를 바꾸면 그대로 동작한다.
   - ISDK `UIsdkGrabbableComponent`(`Plugins/MetaXRInteraction/Source/OculusInteraction/Public/Interaction/IsdkGrabbableComponent.h`): 감지 유형은 HandGrab만(기본값, `:184`), 입력 방식은 **Palm만**(`SetGrabInputMethodAllowed(Pinch, false)`, `:146`; 기본 허용 목록은 Palm·Pinch, `:246-248`).
   - 움직임은 자체 transformer(`IIsdkITransformer` — `Interaction/Grabbable/IsdkITransformer.h:129-175`, `BeginTransform`·`UpdateTransform`·`EndTransform`)로 만든다. `UIsdkGrabTransformerComponent`(`Interaction/Grabbable/IsdkGrabTransformerComponent.h:94`)에 붙인다.
     - **위치:** 손을 따라간다(잡은 순간의 손-물체 상대 위치 유지).
     - **회전(한 손):** Yaw(월드 수직축)는 제한 없이 손을 따르고, 기울기(한쪽 끝을 들거나 내림, 자기 축 둘레로 굴림)는 **45°(자리값)**까지만.
       - 한도 값: 처음 초안의 15°는 Claude가 근거 없이 정한 자리값이었다. 2026-10-11 사용자가 "너무 제한적, 180°는 아니어도 어느 정도는 돌아야"라고 해 45°로 올렸다(Claude 제안 값, VR에서 확인). 45°는 두 손 높이 차로 한쪽 끝을 자연스럽게 드는 범위를 덮으면서, 자유 회전(U-03 제외)이 아니고, 세운 골프백을 눕히는 동작(D5)은 여전히 못 한다.
       - 참고: 트렁크 입구 높이 70 cm 때문에, 가로로 든 골프백(길이 120·지름 28 cm)이 입구를 지날 수 있는 기울기는 약 21°까지다(120·sinθ + 28·cosθ ≤ 70). 더 큰 기울기는 트렁크 밖에서 들고 다닐 때 쓰인다. 한도는 형상으로 막히는 것을 대신하지 않는다 — 차체·트렁크 충돌이 막는다. 기울기와 Yaw는 손이 어떤 자세여도 끊기지 않게 나눈다(오일러 각을 축별로 자르면 Pitch ±90° 근처에서 Yaw가 180° 뒤집힌다 — 리뷰 R1-2).
     - **기울기 한도의 기준은 처음 놓인 자세(받침대 위에 눕힌 자세)다.** 잡을 때마다 기준을 새로 잡지 않는다. 다시 잡아도 기울기(자기 축 둘레 회전 포함)가 쌓이지 않는다(첫 VR 시험에서 쌓여 56°까지 감 — 리뷰 R3-2).
     - **두 손(D6):**
       - 두 번째 손이 잡는 순간, 두 손바닥 위치를 골프백 위의 두 잡은 점으로 기억한다. 첫 손의 잡은 점도 그 순간 다시 잡는다(rebase, 튐 없음).
       - 방향은 두 손 위치로만 정한다. 두 손을 잇는 방향이 처음과 비교해 수평으로 돈 만큼 Yaw를 돌린다. 높이 차로 생기는 기울기는 위 기울기 한도 안으로 자른다. 손목 회전은 쓰지 않는다 — 두 점으로는 자기 축 둘레 회전을 알 수 없으므로 그 회전은 두 손 모드 시작 때 값을 유지한다.
       - 위치: 두 손 사이 거리가 그대로면 멈춘 손 쪽 잡은 점은 그 손에 그대로 붙어 있어야 한다. 거리가 변하면 크기를 바꾸지 않고 오차를 두 점에 나눠 진다(예: 두 잡은 점의 가운데가 두 손의 가운데를 따름).
       - 두 손이 너무 가까워 방향을 믿을 수 없으면 한 손처럼 다룬다(기준 거리는 구현자).
       - 한 손을 놓으면 남은 손으로 한 손 모드(그 순간 rebase). 두 손 모두 놓으면 아래 "놓기".
       - 잡은 손 중 하나라도 추적을 잃으면 골프백 전체를 보류한다(아래 "추적 손실 보류"). 잃은 손이 돌아오면 두 손 모두 그 순간 기준으로 rebase.
       - ISDK: `MultiGrabBehavior`를 `MultiGrab`으로 하고 두 손 transformer는 `SetMultiGrabTransformerObject`로 넣는다(`IsdkGrabTransformerComponent.h:171, 259`). 잡은 손 수가 바뀌면 ISDK가 End→Begin을 다시 부른다(`IsdkGrabTransformerComponent.cpp:113-127, 246-299`).
     - **충돌 — 접촉 응답(D7):** 차체·트렁크를 뚫지 않는다(접촉 여유 0.05 mm 그대로). 손이 끄는 자세(요청 자세)로 바로 못 가면, 겹치지 않는 범위에서 요청 자세에 가장 가깝게 간다.
       - **미끄러짐(이동):** 처음 닿은 면까지 간 뒤, 남은 이동에서 면을 파고드는 성분만 빼고 나머지(면을 따라가는 성분)는 계속 간다. 두 면에 동시에 닿으면(바닥+옆벽, 입구 모서리 안쪽) 두 면이 만나는 선을 따라 간다. 한 frame에 되풀이하는 횟수에는 상한을 둔다.
       - **걸린 곳을 축으로 회전:** 요청 회전을 물체 중심 기준으로 했을 때 겹치면, 겹친 깊이만큼 겹침 반대 방향으로 밀어낸다. 그러면 걸린 곳은 면에 붙어 있고 나머지가 돈다. 밀어내도 겹치면 회전을 줄여 겹치지 않는 만큼만 돈다. 그래도 안 되면 이전 회전을 유지한다.
       - **물리가 아니다:** 움직임은 요청 자세에서만 나온다. 골프백은 요청 자세 쪽으로만 움직이고, 요청에 닿거나 더 갈 수 없으면 멈춘다. 요청을 지나치거나 요청과 무관한 쪽으로 미끄러지지 않는다.
       - **밀어냄 속도 상한(초당, 자리값):** 걸린 곳 축 회전의 밀어냄 거리는 초당 상한 × frame 시간으로 제한한다. 한 frame에 다 못 돈 회전은 다음 frame들에서 이어서 돈다 — 손이 멈춰 있어도 요청 자세까지. 상한은 큰 회전 요청이 한 frame에 튀지 않게 하는 것이고, frame당 값으로 두면 이 PC(약 15 fps)와 회사 PC(72–90 fps)에서 같은 동작이 5–6배 다르게 된다(리뷰 R6-1).
       - 접촉 응답 결과도 기울기 한도(처음 놓인 자세 기준 45°)를 지킨다. 두 손 모드의 요청 자세 계산(D6)은 그대로이고, 접촉 응답은 그 요청에만 건다. 보류 중에는 움직이지 않는다.
       - **접촉 응답은 손으로 들고 있을 때만 쓴다.** 보조 안착(막히면 낙하로 바뀜)과 수직 낙하(처음 닿는 면에서 멈춤)는 지금 그대로다.
       - **"막힘"은 접촉이 아니라 요청을 못 따라간 것이다:** 요청 자세와 실제 자세의 차이가 위치 2 cm 또는 회전 5° 이상이면 막힘, 위치 1 cm·회전 2.5° 미만으로 줄면 해제한다(자리값, 히스테리시스 — 미끄러지는 동안 색·소리가 깜빡이지 않게). 미끄러지거나 걸린 곳을 축으로 도는 중이라도 차이가 그 안이면 "잡힘"이다.
   - **던지기 없음:** `UIsdkGrabTransformerComponent`의 Throwable 설정(같은 헤더 "InteractionSDK|Throwable" 범주)을 끈다. 놓을 때 속도를 이어받지 않는다.
   - **놓기:**
     - 목표 근처(위치 10 cm·각도 20° 안 — 자리값)이고 목표 자세가 겹치지 않으면 → 목표 자세로 0.2 s 동안 옮겨 안착한다("보조 안착"으로 기록).
     - 그 밖 → 그 자리에서 수직으로 떨어져 처음 닿는 면에서 멈춘다. 일정 속도, 회전·튕김 없음.
   - **추적 손실 보류:** 잡은 손의 위치가 무효이거나 신뢰도가 Low면 물체를 그 자리에 멈춘다("보류" 표시). 보류 중 ISDK가 놓기(release)를 보내도 놓기로 처리하지 않는다. 손이 다시 High가 되는 첫 프레임에 손-물체 상대 자세를 다시 잡는다(rebase — 끊긴 동안의 손 이동을 적용하지 않는다). 손 상태는 P0-a처럼 `UOculusXRInputFunctionLibrary`(`IsHandPositionValid`·`GetTrackingConfidence`)로 읽는다. Native OpenXR에서 High는 손목 VALID+TRACKED다(P0-a 명세 §4-4).
   - **상태 표시:** 평상·잡을 수 있음(손바닥이 가까움)·잡힘·막힘·보류·안착·놓임(목표 밖). P0-b R1-1 방식(원래 재질 보존, 덧입힘)으로 색을 바꾼다. 막힘·보류에는 짧은 소리도 낸다(촉감이 없다).
     - **"안착"은 적재 영역 안에 겹침 없이 멈췄을 때만이다**(보조 안착이든 낙하든). 적재 영역은 아래 3번. 목표 밖에서 멈춘 것은 "놓임"이고 안착 색을 쓰지 않는다. 촉감이 없어 색이 유일한 결과 신호다(리뷰 R1-4).
   - 상태 변화 이벤트(`BlueprintAssignable`): 잡힘·놓임·안착. 안착 이벤트는 위 정의대로 목표 안일 때만 보낸다. 기능 명령 연결은 P3 범위.
3. **적재 목표** (`AVBoRLoadTarget`)
   - **목표 자세**(위치·회전): 정적 적합성(그 자세에서 겹치지 않는지)과 보조 안착(10 cm·20° 안이면 그 자세로 옮김)에만 쓴다. 안내 표시도 이 자세에 골프백 크기로 그린다.
   - **적재 영역**(트렁크 안 공간 상자): "목표 안·안착"은 골프백의 충돌 형상이 이 상자 안에 다 들어 있고 겹침이 없는 것이다. 목표 자세와 몇 cm 달라도 트렁크 안에 겹침 없이 놓였으면 안착이다. 목표 자세와 같은 크기 상자로 판정하면 정확히 그 자리가 아니면 모두 "목표 밖"이 된다(리뷰 R4-1).
   - P1 시험대는 트렁크 안쪽 폭·깊이·높이(바닥부터 천장 판까지)를 적재 영역으로 넘긴다. 값은 트렁크 자리값을 따라간다.
   - **목표 자세(골프백 크기 안내 상자)는 적재 영역 안에 있어야 한다.** 부모 기본값끼리도 그렇다 — 값을 안 바꾼 목표에서 보조 안착이 "목표 밖"으로 끝나면 안 된다. 그래도 보조 안착이 적재 영역 밖으로 끝나면 설정 오류이므로 경고 로그를 남긴다(조용한 실패 방지, 리뷰 R5-1).
   - 반투명 안내 표시(켜고 끔). 계획서 §3 "도착 이후 표시는 줄인다"에 따라 기본 켬, 프로퍼티로 끔.

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- **골프백 크기·형상은 바뀌지 않는다.** 안착 보조가 크기를 줄이거나 형상을 바꿔서 넣지 않는다(계획서 §5 "안착 보조가 차체 관통이나 크기 변경을 숨겨서는 안 된다"). 두 손 간격이 변해도 크기는 그대로다.
- **충돌 판정 형상이 보이는 형상보다 크게 튀어나오지 않는다.** 원통을 자기 축 둘레로 돌려도 판정 형상이 커지지 않는다(리뷰 R3-2).
- **보이는 메시가 차체·트렁크를 뚫지 않는다.** 막히면 막힌 채로 보인다. 보조 안착도 목표 자세가 겹치면 하지 않는다.
- **골프백은 손의 요청으로만 움직인다.** 접촉 응답(D7)이 스스로 미끄러지거나 밀려나는 움직임을 만들지 않는다. 같은 요청이 이어지면 요청 쪽으로만 움직이다 멈추고, 요청을 지나치지 않는다.
- **접촉 응답은 frame 속도에 따라 달라지지 않는다.** 같은 손 움직임이면 15 fps와 90 fps에서 결과가 같다(R6-1).
- **손을 뻗지 않고는 잡을 수 없다.** 원거리·레이 잡기는 계속 막혀 있다(P0-b R2-1).
- **던져지지 않는다.** 놓을 때 속도 0, 추적 복구 때 튐 없음.
- **P0 코드와 시험은 그대로 동작한다.** 손 리그 Pawn의 잡기 허용 기본값은 꺼짐이고, P0-b 시험대는 poke만 쓴다. 기존 `vBoR.*` 시험이 모두 통과한다.
- 샘플 플러그인 참조 없음(Agent-Workflow §5.4). `Config/DefaultEngine.ini`의 MetaXR 설정 유지.

| 보조 안착·수직 낙하 중 접촉 | 지금 그대로(보조 안착은 막히면 낙하, 낙하는 처음 닿는 면에서 멈춤). 미끄러지지 않음 | 기존 시험 그대로 통과, 기울어진 면에 떨어져도 옆으로 미끄러지지 않음 |
| 손을 크게 비틂 | Yaw는 따르고 기울기는 한도(45°) 안 | 회전 제한 계산 |
| 손을 90° 넘게 꺾음(Pitch가 ±90°를 지나감) | 물체 Yaw가 튀지 않음(연속) | 손 기울기를 85°→95°로 조금씩 바꿀 때 frame 사이 물체 Yaw 변화가 작음 |
| 목표 근처에서 놓기, 목표 자세가 비어 있음 | 0.2 s 보조 안착, "보조"로 기록 | 판정 함수: 거리·각도·겹침 조합 |
| 목표 근처지만 목표 자세가 겹침 | 보조 안착 안 함, 낙하 | 같은 판정 함수 |
| 목표 밖에서 놓기 | 수직 낙하, 처음 닿는 면에서 멈춤, 회전·튕김 없음. "놓임(목표 밖)" 표시, 안착 색·안착 이벤트 없음 | 낙하 위치 계산, 목표 밖 정지 시 안착 이벤트 0 |
| 트렁크 안이지만 보조 범위 밖(목표 자세에서 수 cm~수십 cm)에서 놓기 | 수직 낙하 뒤 적재 영역 안·겹침 없음이면 "안착"(초록, 안착 이벤트) | 목표 자세에서 옆으로 20 cm 떨어진 트렁크 안 낙하 → 안착 |
| 일부가 트렁크 밖(입구·범퍼 턱 위)에 걸친 채 멈춤 | "놓임(목표 밖)" | 적재 영역 경계를 넘은 자세 → 목표 밖 |
| 자식 메시에 simple collision이 없음 | 시작 로그·패널에 경고. 조용히 못 움직이는 상태로 두지 않음 | 충돌 없는 메시로 시작 → 경고 문구 |
| 적재 영역을 안 바꾼 목표(부모 기본값)에서 보조 안착 | "안착"(초록, 안착 이벤트) | 기본값 목표 + 120 cm 골프백 보조 안착 → 안착 |
| 적재 영역이 목표 자세보다 작게 설정됨 | 보조 안착 뒤 "놓임(목표 밖)" + 설정 오류 경고 로그. 시험대 배치(`R`) 때는 경고 없음 | 영역 < 목표 → 경고 1회, 시험대 배치 → 경고 0 |
| `B`로 골프백만 되돌림 | 시험대·트렁크 위치 그대로, 누적 기록 유지, 시도 번호 +1, 잡고 있던 손 세션은 끝남 | 되돌리기 전후 트렁크 변환 같음, 누적 값 유지 |
| 한 손으로 잡은 채 다른 손으로 잡음 | 두 손 모드, 그 순간 골프백이 움직이지 않음 | 두 번째 손 잡기 frame의 물체 변화 0 |
| 두 손 중 왼손 고정, 오른손만 왼손 둘레로 돎(거리 유지) | 왼손 쪽 잡은 점은 왼손에 그대로, Yaw는 오른손이 돈 만큼 | 왼손 잡은 점 위치 변화 ≈ 0, Yaw 변화 = 두 손 방향 수평 각 변화 |
| 두 손 높이 차가 커짐 | 기울기 한도(45°) 안 | 기울기 한도 |
| 두 손 간격이 늘거나 줄어듦 | 크기 그대로 | scale 불변 |
| 두 손이 거의 붙음 | 한 손처럼 다룸, 방향이 튀지 않음 | 거리 0 근처에서 Yaw 변화 작음 |
| 두 손 중 한 손을 놓음 | 남은 손으로 한 손 모드, 튐 없음 | 놓은 frame의 물체 변화 0 |
| 두 손 중 한 손 추적 손실 | 골프백 전체 보류, 돌아오면 두 손 rebase, 튐 없음 | 보류 중 이동 0, 복구 frame 변화 0 |
| 잡기·놓기를 여러 번 반복 | 기울기·자기 축 회전이 처음 놓인 자세 기준 한도(45°)를 넘지 않음 | 반복 뒤에도 한도 유지 |
| 원통이 자기 축 둘레로 돈 채 바닥·턱 근처 | 보이는 원통이 닿기 전에는 막히지 않음 | 판정 형상이 보이는 형상과 같음(OBB 모서리로 일찍 막히지 않음) |
| 손바닥이 스치듯 지나감(쥐지 않음) | 잡히지 않음 | — (기기 확인) |
| 놓는 순간 손이 빠르게 움직임 | 속도를 이어받지 않음 | 놓은 뒤 물체 속도 0 |

## 5. 구현자가 정할 것

- transformer 안에서 제약을 거는지, 물체 쪽에서 결과를 보정하는지. 근거를 보고한다.
- 충돌 확인 방법(이동 sweep, 회전 겹침 검사)과 충돌 채널.
- 접촉 응답(D7)의 구현: 직접 구현할지 엔진 movement component를 쓸지, 한 frame 되풀이 횟수, 밀어냄 상한 값, 회전을 줄이는 탐색 방법, 여러 면과 동시에 겹칠 때 밀어냄 방향을 합치는 방법. 근거를 보고한다.
- ISDK release 이벤트와 추적 손실 판정의 순서를 어떻게 맞추는지.
- Throwable을 끄는 정확한 프로퍼티(헤더 경로:줄).
- 잡기 판정 형상(`ColliderMode`, 같은 헤더 `:166`, `:198`).
- 측정·판정 로직을 엔진 없이 시험할 수 있는 구조체로 나누는 방식.

## 6. 완료 조건
