## 1. 왜 만드는가

- 자유모드(P5)의 실내 조작 목록(U-11)에 노브가 있다. 평가 단계(01–20)에는 넣지 않는다.
- 감싸 쥔 노브는 잡은 점이 축 위에 있어 1축 부품으로 돌릴 수 없다(D1). 엄지·검지 굴림(U-06)은 회사 PC 실측 뒤 따로 다룬다.

## 2. 범위

### 만들 것

**1. 노브 부모** — `AVBoRKnob`
- D1 구성, D2 각도, D3 잡기, D4 단계, D5 놓기, D6 추적 손실, D7 피드백·읽기 함수.
- 단계 각도·히스테리시스·튐 기준·잡는 상자 여유·표시 자리는 편집 가능한 프로퍼티다.
- 설정 검사는 `PreInitializeComponents`에서 한다(P5d R1-1). 검사 대상은 메시 없음, 단계 각도 음수, 히스테리시스 음수, 단계가 있을 때 히스테리시스 ≥ 단계 각도의 절반이다. 걸리면 경고하고 잡기를 끈다.

**2. P3 근사 차** — `AP3VehicleMock`
- D8. 노브를 공개 프로퍼티로 둔다. 자리값 분류 이름에 "근사"가 드러나게 한다.

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- 기존 `vBoR.*`가 모두 그대로 통과한다. 특히 1축 부품(P2b·P2d·P5a–P5c), 휠(P5d), 룸미러(P5e), P3 흐름.
- 근사 차의 기존 부품 자리와 동작은 그대로다.
- 차 원점 피벗 보정을 지킨다: 노브 Actor 원점 = 차 원점, 쉬는 메시 = 원래 world 자리.
- "추적 손실은 보류"를 지킨다: 다시 인식될 때 그동안의 손 이동을 한 번에 적용하지 않는다.
- ISDK 포인터 이벤트 안에서 SDK 상태를 바꾸지 않고, 사용자 이벤트·소리도 내지 않는다(P2b R1-3, P5b R1-1).
- 금지 조작을 쓰지 않는다: 자유 6DoF·던지기·원거리 잡기는 없다(축 하나 둘레 비틀림만).
- 근사 형상임을 드러낸다(이름·주석·로그).

## 5. 구현자가 정할 것

- 클래스·컴포넌트·프로퍼티 이름과 분류. 이벤트 이름은 `OnKnobStep` 예시.
- 각도·단계 계산을 엔진 없이 시험할 수 있는 구조체로 뺄지(권장, 룸미러 `FVBoRTwoAxisMotion`처럼).
- 각도를 `Tick`(권장, `TG_PostUpdateWork`)과 변환기 중 어디서 계산할지. 어느 쪽이든 사용자 이벤트·소리는 `Tick`이다. 변환기는 대상을 움직이지 않는 얇은 변환기가 쉽다(룸미러 `VBoRTwoAxisPart.h:28-42`).
- 회전 표시 모양·색, 받침 크기·색, 잡는 상자 여유(1축 부품 `GrabMarginCm` 1 cm에서 출발. ISDK 손바닥 판정 구는 반지름 4 cm, `Public/Interaction/GrabDetectors/IsdkHandGrabDetector.h:134`).
- 받침을 근사 차의 생성자 컴포넌트로 둘지, `BeginPlay`에 만들지. 생성자 컴포넌트면 `EndPlay`에서 지우지 않는다(Actor를 지울 때 엔진이 정리함 `Runtime/Engine/Private/LevelActor.cpp:1051`, P5e 리뷰 참고).
