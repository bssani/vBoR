## 0. 결정

| # | 결정 | 내용 |
|---|---|---|
| D1 | **새 클래스 없이 `AVBoRAxisPart`에 걸림 옵션을 더한다** | 계획서 §5 008: "`AVBoRAxisPart` + 걸림 위치 옵션". 방향지시 레버(§5 마지막 줄)가 이 옵션을 다시 쓴다. 옵션은 놓을 때 동작(`Release`, `VBoRAxisPart.h:23`)의 새 값(예: `Detent`)으로 켠다 — 지금 `Return`(0으로 복귀)·`Stay`(그 자리) 옆에 "확정된 걸림으로"가 들어가는 자리다. **회전(`Rotate`)만 받는다.** 기존 `Return`·`Stay` 부품의 동작은 한 줄도 바뀌지 않는다 |
| D2 | **걸림 위치 = 쉬는 자세 기준 각도 목록, 값이 커지는 쪽이 "위"** | 걸림 각도(deg)는 쉬는 자세(값 0 = 메시 원래 자리, U-09)에서 잰 값이고 **오름차순**이다. 시작 위치는 목록의 index로 정한다. 기어 예: −20° / 0° / +20° = **하단 / 중단 / 상단**, 시작 = 중단(index 1). 실제 CAD 레버는 가운데(중단) 자세로 올 가능성이 커서 중단을 쉬는 자세 0으로 둔다. **이동 범위는 첫 걸림부터 끝 걸림까지**이고, 걸림 부품에서는 `MaxAngleDeg`를 쓰지 않는다. 상단 너머·하단 너머로 미는 입력은 INT-008에서 미정이라 끝 걸림에서 멈추게만 한다 |
| D3 | **전환은 잡고 있을 때만, 확정 위치 기준, 한 판정에서 이어서** | 확정 위치가 i일 때: 값 ≥ 걸림[i] + **위쪽 기준**이면 i+1로, 값 ≤ 걸림[i] − **아래쪽 기준**이면 i−1로 간다("이상"이라 경계 포함). 바뀐 뒤 같은 판정에서 새 위치 기준으로 다시 본다 — 손을 떼지 않고 상단에서 하단까지 밀면 중단을 거쳐 두 번 바뀌고, 한 frame에 두 기준을 넘어도 순서대로 두 번 바뀐다(INT-008 "연속 이동"). 바뀔 때마다 이벤트(새 위치 index) 1번·딸깍 소리(`StateAudio`, `VBoRAxisPart.cpp:149-151`)·로그. 위·아래 기준은 따로 둔다. 기어 예: 15° / 15°(사용자 예시, 확정값 아님). 시작할 때는 이벤트를 내지 않는다 |
| D4 | **놓으면 확정된 걸림의 각도로 간다** | 위·아래 어느 쪽이든 `ReturnDegPerSecond`(`VBoRAxisPart.h:84`, 180 deg/s) 속도로 확정 각도까지 가서 멈춘다(넘지 않음). 기준 미만에서 놓으면 원래 위치로, 전환한 뒤 놓으면 새 위치로 간다. 가는 동안과 추적 손실 보류 중에는 전환을 판정하지 않는다. 가는 중에 다시 잡으면 그 각도에서 이어서 손을 따른다. 지금 `Return`은 0 쪽으로만 줄인다(`VBoRAxisPart.cpp:306-311`) |
| D5 | **설정 검사: 어기면 경고하고 잡기를 끈다** | 걸림 2개 이상, 엄격한 오름차순, 모두 ±170° 안, 시작 index가 목록 안, 위·아래 기준 > 0, 이웃 걸림 간격 s마다 **위쪽 기준 ≤ s, 아래쪽 기준 ≤ s, 위쪽 + 아래쪽 > s**, `Movement = Rotate`. 하나라도 어기면 이유를 담은 경고를 한 번 남기고 잡기를 끈다 — 메시가 없을 때와 같은 방식(`VBoRAxisPart.cpp:167-171` 충돌 끔, `:178` Palm 입력). 각도는 시작 걸림(index가 유효할 때), 아니면 쉬는 자세 0. **이유:** 위 + 아래 ≤ s이면 전환한 순간 반대 조건도 이미 참이라 매 frame 오간다(예: 간격 20°, 기준 5°/5° → +5°에서 상단으로 바뀌는데 되돌림 조건 "≤ 20 − 5 = 15°"가 이미 참). 기준 > s이면 끝 걸림까지 가지 못한다(범위가 끝 걸림에서 막힘) |
| D6 | **걸림 부품은 열림·닫힘 이벤트와 열림 색을 쓰지 않는다** | 지금 열림·닫힘은 비율 문턱(`OpenThreshold` 0.8·`ClosedThreshold` 0.05, `VBoRAxisPart.cpp:327-328`)이라 3단 레버에서는 상단 근처에서 "열림" 소리가 나는 식으로 뜻이 없다. 걸림 부품에서는 `OnPartOpened`·`OnPartClosed`를 내지 않고, 덮개 색은 hover·잡기만 쓴다(`:331`의 `OpenColor` 빼기). `OnPartReleased`는 그대로 낸다 |
| D7 | **시작 자세는 `BeginPlay`에서 놓는다** | 쉬는 축(`RestPivot`)은 `OnConstruction`(`VBoRAxisPart.cpp:158`)과 `PreInitializeComponents`(`:176`)에서 **`AxisPivot`의 지금 자세로** 잡힌다. 그 전에 `AxisPivot`을 시작 각도로 돌려 두면 쉬는 자세가 시작 각도로 틀어지고, 에디터에서 construction이 다시 돌 때마다 누적된다. 그래서 `OnConstruction`은 지금처럼 값 0(쉬는 자세)으로 두고, `BeginPlay`에서 값 = 시작 걸림 각도, `AxisPivot` = 그 자세로 놓는다. 에디터 화면에는 쉬는 자세(= 기어는 중단)가 보인다 |
| D8 | **끝 버튼: 레버 끝의 `AVBoRPokeButton`, 눌림 이벤트만** | U-11 "끝 버튼은 눌림 이벤트만". 레버 `AxisPivot`의 자식이라 레버와 함께 움직인다(P4b가 움직이는 판에 버튼을 붙인 방식, `VBoRPoweredPanel.cpp:53-61`). 누르는 면(버튼 +Z, `VBoRPoweredPanel.h:78-80` 주석)은 레버 끝 바깥(근사 차 +Y)을 향한다 — INT-008은 누름 방향을 사진으로 정하지 않았으므로 근사 자리값이다. **레버 이동·잡기와 아무 관계를 두지 않는다**(INT-008 "역할·이동과의 관계 미정"): 눌러도 레버가 안 움직이고, 레버를 잡은 중에도 눌림 이벤트는 그대로 난다. 단계 태그를 붙이지 않는다 — P3 진행기는 단계 데이터의 태그로 찾은 버튼만 센다(`VBoRScenarioRunner.cpp:188-190`). 판정 영역은 키우지 않는다(`HitAreaScale` 1, 근처에 몰린 버튼 없음). 근사 차가 버튼을 공개 프로퍼티로 두어 사용자가 이벤트를 묶는다 |
| D9 | **근사 차: 운전석 스티어링 컬럼 오른쪽, 핸들 판 뒤·대시보드 아래** | INT-008의 "위 또는 아래로 밀어"와 사진 설명("긴 몸체·꺾인 연결부·끝 버튼")을 보면 스티어링 컬럼에 달린 레버로 보인다. 실제 자리·축은 미정이므로 **자리값 프로퍼티**로 둔다. 차 원점 피벗 흉내(Actor 원점 = 차 원점, 축만 자리로, 메시는 `MeshRestFromRoot`, U-09 — 글러브박스 손잡이와 같음). 예: 축 (39, −30, 70) cm, 레버 16 × 2 × 2 cm(축에서 차 +Y로 뻗음), 회전축 = 차 X(값 + = 끝이 위로), 걸림 −20 / 0 / +20°, 기준 15 / 15°, 버튼 1.6 × 1.6 × 0.6 cm를 레버 끝면에. **겹침 확인:** 핸들 판은 X 32.5–37.5·Y −52–−22·Z 72–102(`P3VehicleMock.cpp:68`), 대시보드는 X 37.5–62.5·Z 79–91(`:26`)이다. 레버는 X 38–40이고, 상단(+20°)에서 끝 윗면이 Z ≈ 76.4라 두 판 모두와 겹치지 않는다. 운전석 눈 (−20, −37, 115)에서 레버 끝 (39, −14, 70)까지 약 78 cm다 |

## 1. 왜 만드는가

- 자유모드(P5)의 실내 조작 목록(U-11)에 기어 레버가 있다. 평가 단계(01–20)에는 넣지 않는다.
- 지금 1축 부품은 놓으면 0으로 돌아가거나(`Return`) 그 자리에 남는다(`Stay`). 기어는 가운데에서 시작해 양쪽으로 가고, 놓으면 확정된 위치로 간다. 방향지시 레버도 같은 옵션을 쓸 예정이라(계획서 §5) 1축 부품에 옵션으로 넣는다.

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- 기존 `vBoR.*`가 모두 그대로 통과한다. 특히 1축 부품(P2b: 범위·복귀·`Stay`·추적 보류·재잡기), 문 손잡이 넘김(P2c·P2d), 글러브박스(P5a), P3 흐름·키 테이블(P4a).
- `Return`·`Stay` 부품은 범위 [0, `MaxAngleDeg`/`MaxTravelCm`], 시작 0, 열림·닫힘 이벤트·색이 지금과 같다. 걸림 코드는 걸림 부품에서만 탄다.
- 차 원점 피벗 보정을 지킨다: 레버 Actor 원점 = 차 원점, 쉬는 자세의 메시 = 원래 world 자리.
- "추적 손실은 보류"를 지킨다: 보류 중에는 값·확정 위치가 그대로고, 복구 때 그동안의 손 이동을 버린다(지금 `Rebase`, `VBoRAxisPart.cpp:79-97`).
- ISDK 포인터 이벤트 안에서 SDK 상태를 바꾸지 않는다(P2b R1-3).
- 근사 차의 기존 부품(문·손잡이·콘솔·글러브박스·도달 버튼·키 테이블·시작 표시) 자리와 동작은 그대로다.
- 끝 버튼의 보이는 크기와 판정 영역은 같다(`HitAreaScale` 1).
- 근사 형상임을 드러낸다(이름·주석·로그).

## 5. 구현자가 정할 것

- 걸림을 켜는 방법(`Release` 새 값 권장), 프로퍼티·이벤트·함수 이름과 분류. 이벤트 인자는 새 위치 index가 필수이고 이전 index는 넣어도 된다.
- 설정 검사 위치와 경고 문구. `PreInitializeComponents`를 권한다 — 스폰마다 한 번 돌고, 잡기 입력(`:178`)을 거기서 정한다. `OnConstruction`은 에디터에서 여러 번 돌아 경고가 반복된다.
- 걸림 부품의 `GetOpenRatio` 값(열림·닫힘 이벤트에 쓰지 않으면 된다).
- 근사 차 프로퍼티 이름과 값(D9 예시는 출발점). 회전 부호(`Axis`·`bReverse`)는 시험으로 "값 + = 끝이 위로"를 보인다.
- 버튼 크기·자리·태그 이름(단계 태그와 겹치지 않게).
