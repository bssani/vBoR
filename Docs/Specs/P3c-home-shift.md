## 0. 결정

| # | 결정 | 내용 |
|---|---|---|
| D1 | **켜고 끄기는 콘솔 변수 하나** | `vBoR.HomeShift`(int, 기본 0 = 꺼짐). 1이면 D2 키가 동작한다.<br>- 에셋·레벨·설정 파일에 저장하지 않는다. 그래서 평가 PC에서는 누가 켜지 않는 한 꺼져 있다.<br>- 꺼져 있으면 D2 키는 아무것도 하지 않는다. 진행자 창 키 처리에서도 "처리 안 함"으로 돌려준다 |
| D2 | **키 다섯 개 — 숫자 키패드** | `NumPadEight` 앞(차 +X), `NumPadTwo` 뒤(−X), `NumPadFour` 운전석 쪽(−Y), `NumPadSix` 동승석 쪽(+Y), `NumPadFive` 원위치.<br>- 한 번에 `HomeShiftStepCm`(기본 100 cm, 정렬 컴포넌트 프로퍼티)만큼 옮긴다.<br>- 방향은 **차 기준**이다: 정렬 컴포넌트를 가진 Actor(근사 차)의 앞·오른쪽 벡터를 수평으로 쓴다. 차가 돌아 있어도 차 앞뒤로 간다. 높이는 바꾸지 않는다.<br>- 게임 입력(Runner `BeginPlay`의 `BindKey`, `VBoRScenarioRunner.cpp:157-170`)과 진행자 창 포커스 키(`HandleOperatorKey`, `VBoRScenarioOperator.cpp:188-195`) 모두에서 같은 함수를 부른다. 반복 키(`bRepeat`)는 무시한다.<br>- **진행자 창 버튼과 단축키 표(`VBoROperator::Shortcuts()`)에는 넣지 않는다.** 개발 도구라서 창을 바꾸지 않는다. 그래서 P5i 시험(버튼 = 키, 글 폭, 주 버튼 하나)은 그대로다 |
| D3 | **옮기기는 정렬 컴포넌트가 한다** | `UVBoRVehicleAlignmentComponent`에 옮긴 양(차 기준 cm, X·Y)을 둔다. 옮기면 Pawn 위치에 그 차이만큼 더한다(회전 그대로). 그리고:<br>- **짧은 밝아짐:** 옮긴 frame에 화면을 검게 했다가 `FadeSeconds` 동안 밝힌다(전환의 둘째 절반과 같은 꼴, `VBoRVehicleAlignmentComponent.cpp:193-194`). 1 m 순간 이동의 멀미를 줄이려는 것이다.<br>- `OnPawnMoved`를 한 번 알린다. 그래서 Runner의 패널 다시 놓기(`VBoRScenarioRunner.cpp:511-514`)가 기존 시점 전환과 같이 동작한다.<br>- 원위치(`NumPadFive`)는 옮긴 양만큼 되돌리고 0으로 둔다.<br>- **옮긴 양이 0이 되는 때:** 컴포넌트가 Pawn을 직접 놓을 때 — 시점 전환·기준 복귀가 Pawn을 옮길 때(`:186-188`), 정렬 적용·다시 적용(`:73`). 이때는 저장값에서 절대 자세를 계산하므로 옮긴 양이 저절로 사라진다. 숫자만 0으로 맞춘다 |
| D4 | **받지 않는 때** | 시점 전환·정렬 다시 적용 암전 중(`IsSwitching()`), 레벨 다시 열기 암전 중(Runner `bReloadPending`)에는 무시하고 기록만 남긴다.<br>- **정렬 상태와는 상관없다.** `NeedsCheck`·`NoSavedValue`에서도 옮긴다. 집에서는 플레이 영역이 바뀌어 `NeedsCheck`가 되기 쉽다(2026-10-19 로그: "suspected guardian change"). 좌석 전환이 정렬을 요구하는 기존 규칙(`AdvanceSwitch` `:168-174`)은 그대로다 |
| D5 | **R은 원위치도 한다** | R(`VBoRScenarioRunner.cpp:472-493`)은 기준 시점에 있으면 Pawn을 옮기지 않는다. 그래서 R에서 D3 원위치를 부른다(옮긴 양이 0이면 아무것도 안 함). R = 처음부터(P4d D6)라는 뜻과 맞춘다 |
| D6 | **보이게 한다** | `vBoR.HomeShift`가 1이면 진행자 창 상태에 옮긴 양을 보인다. 예: `Home shift ON · +2.0 m front · −1.0 m side`. 꺼져 있으면 아무것도 보이지 않는다. 자리(기존 줄에 붙이기 또는 새 줄)는 구현자가 정한다. 기록 줄에도 남긴다(`집 시험 옮기기 +X 100 cm → (200, −100)`) |

## 1. 왜 만드는가

- 사용자가 집에서 VR로 근사 차를 시험한다. 앞(키 테이블·출발 표시)과 뒤(트렁크·리프트게이트·박스 받침)를 보려면 몇 m를 걸어야 하는데 방이 좁다.
- 차를 줄이면 기어·노브·미러·박스의 손 조작이 실제 크기와 달라진다. 오늘 피드백(P5n)이 그 손 조작이므로 실제 크기를 지킨다.

## 2. 범위

### 만들 것

1. 콘솔 변수 `vBoR.HomeShift`(D1).
2. 정렬 컴포넌트의 옮기기·원위치·옮긴 양(D3), 받지 않는 때(D4).
3. Runner 키 다섯 개(게임 입력·진행자 창 포커스), R의 원위치(D2·D5).
4. 진행자 창 상태·기록(D6).
5. 자동화 시험 §4.

### 범위 밖 — 하지 말 것

| 하지 말 것 | 이유 |
|---|---|
| 차·부품 축소 배율 | 사용자 선택(U-16 ①) — 실제 크기 유지 |
| 참가자 손 입력·진행자 창 버튼으로 옮기기 | 개발 도구다. 참가자 텔레포트 금지(AGENTS.md "확정된 제약")와 섞지 않는다 |
| 높이·회전 옮기기, 연속 이동(누르고 있으면 계속) | 사용자: 앞뒤·좌우 1 m씩 |
| 콘솔 변수를 ini·레벨에 저장 | 평가 PC에서 켜진 채 남지 않게 |
| 03·07 경로·단계 규칙을 옮긴 자리에 맞춰 바꾸기 | 개발 도구다. 옮긴 뒤 도착 판정이 이상해도 그대로 둔다 |

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- `vBoR.HomeShift`가 0이면 지금과 똑같이 동작한다. Pawn·패널·기록·진행자 창이 그대로다.
- 진행자 창 버튼·단축키 표·`EVBoROperatorButton`·`EVBoRFlowCommand`는 바꾸지 않는다.
- 좌석 시점 자세는 옮긴 양과 상관없이 지금과 같다(저장값에서 절대 계산 — P3 E11 "전환 오차 누적 방지").
- 정렬 상태 판정(`CheckEnvironment`)·좌석 전환 규칙은 그대로다.
- 기존 단언은 바꾸지 않는다.

## 5. 구현자가 정할 것

- 옮긴 양을 담는 형식과 함수 이름.
- 콘솔 변수를 둘 파일(Runner 또는 정렬 컴포넌트 .cpp).
- 진행자 창 상태에서 보일 자리와 정확한 글.
- 시험에서 콘솔 변수를 켜고 끄는 방법(시험 끝에 0으로 되돌린다).

## 6. 완료 조건

1. §2의 1–5가 들어 있다.
2. §4 시험이 모두 자동화로 통과한다. 기존 `vBoR.*`도 통과한다.
3. non-unity(`-Module=vBoR`)·unity 빌드에서 vBoR 경고·오류가 0이다. 전체 시험은 최종 트리로 한 번 돌린다.
4. AGENTS.md 보고 ①–⑤를 커밋 본문과 `HANDOFF.md`에 남긴다.
5. 시험 상태는 `not-tested`다.

## 7. 로컬에서 확인할 것 — 사용자(집, VR)

1. 에디터 Output Log의 Cmd 칸(또는 `~` 콘솔)에 `vBoR.HomeShift 1`을 넣고 VR Preview를 시작한다.
2. 키패드 8·2·4·6으로 차 앞(키 테이블·출발 표시)과 뒤(트렁크·박스 받침)까지 가 본다. 5로 원위치.
3. 옮길 때의 짧은 밝아짐이 불편하지 않은지 본다.
4. 진행자 창에 옮긴 양이 보이는지 본다.
