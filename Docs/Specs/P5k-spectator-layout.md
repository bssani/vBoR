## 0. 결정

| # | 결정 | 내용 |
|---|---|---|
| D1 | **시야는 화면 높이 전체, 왼쪽에 붙임** | 창 비율 A(가로/세로), 시야 비율 E(`EyeAspect`, 4:3 그대로), 오른쪽 칸 최소 폭 m(창 높이에 대한 비율, 새 프로퍼티 `MinPanelWidth`, 기본 0.37 — 1080에서 약 400 px)으로 계산한다. 시야 높이 h = min(1, (A − m) / E). **시야:** x 0 → h·E/A, y (1 − h)/2 → (1 + h)/2(높이가 줄면 세로 가운데). **오른쪽 칸:** x h·E/A → 1, y 0 → 1. 16:9 창이면 h = 1, 시야 x 0–0.75(1440 × 1080), 칸 x 0.75–1(480 px). 칸이 최소 폭보다 좁아지는 창(16:10·4:3)에서만 시야가 줄어든다. 시야 밖 빈 곳은 검게 지운다(`bClearBlack`). P5h의 `BandHeight`는 없앤다(이 배치에는 띠가 없음) |
| D2 | **UI 텍스처는 오른쪽 칸에만** | 배치 구조체의 텍스처 영역(`TextureRectMin`·`Max`, 엔진 `Runtime/HeadMountedDisplay/Public/HeadMountedDisplayTypes.h:170`)을 오른쪽 칸으로 둔다. 지금처럼 화면 전체에 늘이지 않는다(창 비율이 바뀌면 글자가 늘어나던 문제가 같이 없어짐 — P5h 리뷰 1회차 참고). 칸은 불투명이다. **렌더 타깃 크기 = 칸의 창 픽셀 크기**(반올림)이고, 칸 크기가 바뀌면 다시 맞춘다(`UTextureRenderTarget2D::ResizeTarget`, 엔진 `Runtime/Engine/Classes/Engine/TextureRenderTarget2D.h:189`). 위젯은 **창 높이 1080을 기준으로 디자인한 크기**로 배치하고, 배율 인자가 있는 `DrawWidget`(엔진 `Runtime/UMG/Public/Slate/WidgetRenderer.h:75`)에 배율 = 칸 높이 px / 1080을 준다. 그리는 크기는 픽셀이고 배치 크기는 그것을 배율로 나눈 값이다(엔진 `Runtime/UMG/Private/Slate/WidgetRenderer.cpp:157`). 그래서 TV가 4K여도 같은 모양으로 커진다 |
| D3 | **칸 안 배치(1080 기준)** | 디자인 `TvBand.dc.html`의 두 배 값이다. 여백 위아래 40 px·좌우 32 px. 위에서부터 ① 꼬리표(P5h D4의 `GETTING READY`·`MISSION k / N`·`FREE MODE`, Bold 40 pt, 강조색, 넘치면 줄바꿈) ② 12 px 아래 미션 문구(Regular 36 pt, 줄바꿈 허용, 남은 높이를 넘으면 말줄임) ③ 빈 공간 ④ 진행 묶음: 작은 제목 `PROGRESS`(16 pt, 보조 글자, 자간 넓게), 막대(높이 12 px), `k of N complete`(20 pt, 보조 글자). `End`로 들어간 자유모드에서는 묶음째 숨긴다(P5h D4) ⑤ 구분선 2 px ⑥ 조작 중 묶음: 작은 제목 `INTERACTING`(16 pt), 그 아래 이름을 **한 줄에 하나씩**(Regular 27 pt, 최근 것부터 최대 둘, 넘치면 말줄임). 이름이 없으면 제목까지 묶음째 숨긴다. 칸 왼쪽에 2 px 선. **글꼴 크기는 pt(96 DPI)다**(디자인 px × 0.75). 꼬리표·미션·부품 크기는 지금 프로퍼티(`LabelFontSize`·`MissionFontSize`·`PartFontSize`)의 기본값만 40·36·27로 바꾸고, 작은 제목(16)·진행 문구(20)는 새 프로퍼티로 둔다 |
| D4 | **색 — 진행자 창과 같은 팔레트** | 칸 바탕 `#131a26`, 꼬리표·막대 `#5b8cff`, 미션·이름 `#eef2f7`, 작은 제목·진행 문구 `#9aa6b8`, 막대 바탕 `#1c2534`, 칸 왼쪽 선·구분선 `#2e3a4e`. sRGB hex를 `FLinearColor::FromSRGBColor(FColor::FromHex(...))`로 바꾼다(엔진 `Runtime/Core/Public/Math/Color.h:123`, `:573`). 지금 있는 `BackgroundColor`·`TextColor`·`AccentColor`는 기본값만 바꾸고, 보조 글자·막대 바탕·선 색은 새 프로퍼티로 둔다. 새 프로퍼티는 모두 `Config`다(P5h R1-1과 같이 `DefaultGame.ini`로 바꿈) |
| D5 | **이름 목록을 줄로 읽는다** | 지금 이름 줄은 `"Interacting: A · B"` 한 문자열이다(`Spectator/VBoRSpectatorModel.cpp:65-71` `Line`). 칸에서는 이름을 줄마다 쓰므로, 최근 것부터 최대 둘을 목록으로 돌려주는 읽기 함수를 더한다. `Line`은 지우지 않는다(P5h E7–E10 시험이 씀). 작은 제목은 지금 `InteractingPrefix` 프로퍼티의 자리를 쓰되 기본값을 `INTERACTING`으로 바꾼다 |
| D6 | **그대로 두는 것** | 관전 경로(P5h D1 — 뷰포트에 올리지 않음, 다시 시도, 헤드셋 없으면 아무것도 안 함), 상태별 문구(P5h D4·D5), 부품 수집·1 s 유지·최대 둘(P5h D6), 다시 그리는 빈도. 헤드셋 화면은 바뀌지 않는다 |

## 1. 왜 만드는가

- P5h 배치는 16:9 TV에서 시야가 1123 × 842이고 양옆과 아래에 빈 공간이 남는다. 새 배치는 시야가 1440 × 1080으로 가로세로 각각 28% 커지고, 남는 480 px에 정보를 둬서 시야를 가리지 않는다.
- 16:9를 꽉 채우면 VR 시야 위아래가 잘린다(P5h D3). 4:3 범위를 지키면서 빈 공간을 없애는 배치다.

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- 기존 `vBoR.*`가 모두 통과한다. **배치를 바꾸는 사용자 결정 때문에 고치는 P5h 시험은 넷뿐이다:** E15(`P3Probe/P5hSpectatorTests.cpp:322-341`, 창 비율별 영역 → 새 값), E16(`:343-355`, `BandHeight` → `MinPanelWidth`), E17(`:357-419`, 띠에 들어감 → 칸에 들어감), E18(`:421-446`, Config 프로퍼티 목록 — `BandHeight`를 빼고 새 프로퍼티를 더함). 다른 P5h 시험(E1–E13)과 다른 시험의 단언은 바꾸지 않는다.
- 헤드셋이 없거나 자동화(`-nullrhi`)에서는 지금처럼 아무것도 만들지 않는다.
- 헤드셋 화면에 관전 UI가 나오지 않는다.

## 6. 완료 조건

1. §2의 1–3이 들어 있다.
2. §4 시험이 모두 자동화로 통과한다. 기존 `vBoR.*`도 통과한다(§3의 넷은 새 기대값으로).
3. non-unity(`-Module=vBoR`)·unity 빌드에서 vBoR 경고·오류가 0이다. 전체 시험은 최종 트리로 한 번 돌린다.
4. AGENTS.md 보고 ①–⑤를 커밋 본문과 `HANDOFF.md`에 남긴다.
5. 시험 상태는 `not-tested`다.

## 7. 로컬에서 확인할 것 — 사용자

### Quest 3 (Link, 에디터 VR Preview, `L_P3_Flow`) + TV
1. TV(16:9)에서 시야가 화면 높이 전체를 쓰고 오른쪽에 정보 칸이 붙는지, 빈 검은 공간이 없는지 본다.
2. TV 시야가 헤드셋에서 보이는 범위와 비슷한지 본다(4:3 — P5h §7-2와 같음). 다르면 `DefaultGame.ini`의 `EyeAspect`만 바꾼다.
3. TV 몇 m 뒤에서 꼬리표·미션·진행·부품 이름이 읽히는지 본다. 작으면 `DefaultGame.ini`로 글꼴 크기를 키운다.
4. 게임 창 크기를 바꾸거나 TV로 옮겨 전체 화면으로 해도 배치가 맞는지 본다.
5. 헤드셋에는 칸이 보이지 않는지 본다(P5h §7-1).
