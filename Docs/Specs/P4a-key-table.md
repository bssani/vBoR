## 0. 결정

| # | 결정 | 내용 |
|---|---|---|
| D1 | **키는 이벤트만 낸다** | 웰컴 라이트(앞·뒤 등), 켬·끔 상태, 진행자 키보드는 사용자가 만든다. 키는 "열림 눌림"·"잠금 눌림" 이벤트만 부른다. 키에는 상태가 없다 |
| D2 | **키 두 개는 기능이 같다** | 들고 다니지 않게 차 앞·뒤 테이블에 하나씩 둔 것이다. 두 키는 같은 이벤트를 부른다. 근사 차는 두 키의 이벤트를 모아 다시 내보낸다(사용자가 한 곳에만 묶으면 된다) |
| D3 | **버튼은 둘(열림·잠금)이고, 키를 쥐지 않은 손으로만 누른다** | 키가 손에 쥐어져 있을 때만, 쥐지 않은 손의 poke만 받는다. 테이블의 키를 집으려 뻗는 손이 버튼을 스치거나, 쥔 손가락이 버튼을 덮어 눌리는 것을 막는다. 버튼은 기존 `AVBoRPokeButton`을 키에 붙여 쓴다(새 버튼을 만들지 않는다) |
| D4 | **쥐기는 자유 6DoF다(키만 예외, U-10)** | ISDK 그대로 쓴다: `UIsdkGrabbableComponent` + `UIsdkGrabTransformerComponent` + `UIsdkGrabFreeTransformer`. 손바닥·pinch 둘 다 받는다. 크기는 바뀌지 않는다(양손 스케일 금지). 다른 손이 잡으면 그 손으로 넘어간다(`SingleGrabTransferToSecond`) |
| D5 | **놓으면 물리로 떨어지고 던질 수 있다(키만 예외)** | ISDK 내장 경로를 쓴다: 잡으면 물리를 끄고, 놓으면 물리를 되돌리며 `UIsdkThrowable` 속도를 준다(`bIsThrowable`). **단, 놓기 직전 표본 구간(`ThrowSettings.SampleSize` 프레임, 기본 8)에 쥔 손 추적이 High가 아니던 프레임이 있으면 속도를 0으로 한다** — 추적 복구 순간의 손 이동이 던지기 속도가 되지 않게(AGENTS.md U-10 예외의 조건).<br>추적 손실로 SDK가 선택을 끝내면 **보류하지 않고** 그대로 떨어뜨린다(속도 0). 키는 테이블로 돌아오므로 다시 집으면 된다. 보류를 만들려면 ISDK 자유 잡기 위에 다시 선택하는 구조가 필요해 단순하지 않다. 다른 부품의 "추적 손실은 보류" 규칙은 그대로다 |
| D6 | **바닥에 닿으면 자기 테이블로 돌아간다 — 같은 Actor를 옮긴다** | 쥐지 않은 키가 바닥 높이(자기 테이블 Actor 원점 Z) + 여유 아래로 내려가면, 그 키 Actor를 자기 테이블 위 자리로 옮기고 속도를 0으로 한다. **새로 만들지 않는다** — 사용자가 Blueprint에서 묶은 이벤트가 끊기지 않게. 바닥은 충돌이 아니라 높이로 판정한다(레벨 바닥 충돌이 없거나 물리 바닥과 어긋나도 동작) |
| D7 | **시작 위치는 차 앞, 차를 바라보는 방향** | 근사 차의 시작 표시(지금 운전석 옆 250 cm)와 "시작 위치" 표시판을 차 앞(+X 쪽)으로 옮기고 차(−X)를 바라보게 한다. 시작 머리 기록 동작은 그대로다 |
| D8 | **단계 01·02는 코드에서 바꾸지 않는다** | 생성자 기본 단계는 바꾸지 않는다(P3 리뷰: 손대지 않은 에셋이 같이 바뀜). 01·02의 규칙은 사용자가 `DA_P3_Scenario`에서 고친다. 이를 위해 근사 차가 만든 키 버튼에 하나씩만 일치하는 태그를 단다(`ButtonPressed` 규칙은 대상이 하나여야 함) |

## 1. 왜 만드는가

- 웰컴 라이트를 접근 거리로 켜는 대신, 참가자가 테이블의 키를 집어 버튼을 누른다(U-10).
- 웰컴 라이트 자체는 사용자가 만든다. 이 명세는 키·테이블·이벤트·시작 위치까지다.

## 2. 범위

### 만들 것

**1. 키 부모** — `Source/vBoR/Interaction/`의 새 Actor (예: `AVBoRKeyFob`)
- 근사 키 메시(크기 프로퍼티, 자리값). 루트가 물리를 시뮬레이션하는 메시다(ISDK 잡기 변환 대상이 이 메시 — 놓을 때 물리 복원·속도를 여기에 준다).
- 잡기: D4. 버튼: D3, `AVBoRPokeButton` 둘(열림·잠금)을 키 메시에 붙인다. 버튼 자리·크기는 프로퍼티.
- 이벤트: `OnUnlockPressed`·`OnLockPressed` (`BlueprintAssignable`, 누른 키를 넘김).
- 놓기·던지기: D5. 되돌리기: D6.
- 자식 Blueprint에서 메시·버튼 자리만 바꾸면 바로 쓸 수 있어야 한다(AGENTS.md 구조 원칙).
- 로그: 버튼 이벤트(어느 키·어느 버튼·누른 손), 쥐기·놓기(던진 속도 cm/s, 0으로 만든 이유), 되돌림. 웰컴 라이트가 없을 때 VR에서 확인하는 수단이다.

**2. 미니 테이블** — 새 Actor (예: `AVBoRKeyTable`)
- 근사 테이블 메시(크기 프로퍼티, 충돌 있음 — 키가 올라앉음).
- BeginPlay에서 자기 키를 하나 만들어 위에 놓는다(키 클래스는 `TSubclassOf` 프로퍼티 — 자식 Blueprint 키를 쓸 수 있게). 키의 "집"이다(D6).

**3. 근사 차** — `AP3VehicleMock`
- 시작 표시·표시판을 차 앞으로(D7). 거리는 기존 `StartOutsideCm`을 그대로 쓴다.
- 테이블 둘: 앞·뒤 자리값 프로퍼티(cm, 차 원점 기준). 차 앞 테이블은 시작 표시와 차 사이의 옆쪽처럼 걸어오는 길을 막지 않는 자리.
- 두 키의 이벤트를 모아 `OnKeyUnlockPressed`·`OnKeyLockPressed`(`BlueprintAssignable`, 누른 키를 넘김)로 다시 낸다(D2).
- 키 버튼 태그 4개, 하나씩만 일치: 예 `Car.FrontKey.Unlock`, `Car.FrontKey.Lock`, `Car.RearKey.Unlock`, `Car.RearKey.Lock`(D8).
- `EndPlay`에서 만든 Actor를 정리한다(기존 문·뚜껑과 같은 방식).

**4. 자동화 시험** — §4 전부

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- 기존 `vBoR.*` 시험이 그대로 통과한다. P3 흐름·시작 머리 기록·착석·문·뚜껑 동작은 그대로다. 시작 표시의 자리만 바뀐다.
- 키의 크기는 쥐어도, 다른 손으로 넘겨도 그대로다.
- ISDK 포인터 이벤트 안에서 SDK 상태를 바꾸는 호출(`ForceCancel` 등)을 하지 않는다(P2b R1-3). 되돌리기 중 잡기 취소가 필요하면 Tick에서 한다.
- 되돌릴 때 키 Actor를 새로 만들지 않는다(D6).
- 근사 형상임을 드러낸다(이름·주석·로그에 "근사", 크기·자리는 프로퍼티).

## 7. 로컬에서 확인할 것 — 사용자

### Quest 3 (Link, VR Preview, `L_P3_Flow`)
1. 시작 표시가 차 앞에 있고 차를 바라보는지 본다.
2. 앞 테이블의 키를 손바닥으로, 한 번은 pinch로 집는다. 손을 돌리면 키도 도는지 본다.
3. **키를 쥔 채 다른 손 검지로 열림·잠금을 누른다.** 로그·버튼 표시·소리로 눌림을 본다. **움직이는 키에서 ISDK poke가 잘 잡히는지는 이번이 처음 확인이다** — 잘 안 눌리면 그대로 알려 준다.
4. 쥔 손 손가락이 버튼을 덮어도 눌리지 않는지 본다.
5. 키를 놓아 떨어뜨리고, 한 번은 던진다. 바닥에 닿으면 앞 테이블로 돌아오는지 본다.
6. 뒤 테이블 키로 2–5를 한 번 더 한다.
7. 키를 쥔 손을 시야 밖으로 뺐다가 돌아온 직후 놓는다. 날아가지 않아야 한다.
