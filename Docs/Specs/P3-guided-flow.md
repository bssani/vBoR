## 1. 왜 만드는가

P0–P2에서 부품(버튼, 골프백, 문, 정렬)을 따로 확인했다. P3는 그것들을 **번호 순서 안내 하나로 잇는다.** 확인할 것:
- 밖에서 시작해 걸어와 시팅벅에 앉았을 때 가상 좌석이 맞는가(D2).
- 손 확인과 진행자 키가 겹쳐도, 단계가 바뀌는 frame에 입력이 와도 단계가 두 번 넘어가지 않는가(T-04).
- 좌석 시점 전환·복귀가 중복 입력에 안전하고, 하차 전에 기준으로 돌아오는가(T-05).
- 도착·응시·추적 손실만으로 관찰을 완료 처리하지 않는가(T-06).
- 사용자가 데이터 에셋만 고쳐 단계 순서·문구·규칙을 바꿀 수 있는가(D1).

1. **시나리오 데이터 에셋** (`UVBoRScenarioAsset : UPrimaryDataAsset`) — 단계 배열 `Steps`. 단계 하나(`FVBoRScenarioStep`):

   | `StepId` (FName) | 원본 시나리오 ID("01"~"20"). 번호를 새로 매기지 않는다(AGENTS.md) |
   | `Instruction` (FText) | 참가자 안내 문구(한국어) |
   | `Rule` (enum) | 완료 규칙: `Confirm`, `Approach`, `Seated`, `ButtonPressed`, `DoorUnlocked`, `DoorOpened`, `DoorLatched`, `Viewpoint` |
   | `TargetTag` (FName) | 규칙이 볼 대상의 태그(액터 또는 컴포넌트 태그) |
   | `DoorOpenDeg` | `DoorOpened`의 각도(자리값 45°. 계획서 §4 "목표 각도는 미정") |
   | `SeatedSeconds` | `Seated`에서 머리가 좌석 영역에 머물 시간(자리값 1.5 s) |
   | `ConfirmBy` (enum) | 규칙을 만족한 뒤 확인이 필요하면 누가 하는지: `None`(규칙만으로 완료), `Participant`, `Operator`, `Either`. `Confirm` 규칙에서는 확인 자체가 완료다 |

2. **안내 진행기** (`AVBoRScenarioRunner`) — 레벨에 하나 놓고 데이터 에셋을 지정한다.
   - **시작 전 검사:**
     - 모든 `TargetTag`·`MarkerTag`가 레벨에서 맞는 종류로 찾아지는지 본다. 없거나 종류가 틀린 것을 패널과 로그에 모두 적고 시작하지 않는다.
     - 정렬 상태가 "적용됨"인지 본다(아래 5번). 아니면 "정렬 필요 — P0-c 레벨에서 C로 저장"을 보이고 시작하지 않는다. 진행자 키로 무시하고 시작할 수 있다. 무시는 로그에 남는다.
   - **진행:** 지금 단계의 규칙을 매 frame 본다.
     - 상태 규칙(문 상태, 접근, 좌석)은 단계 시작 때 이미 만족해도 완료로 본다.
     - `ButtonPressed`는 단계 시작 뒤 누른 횟수가 늘어야 한다.
     - 규칙을 만족하고 `ConfirmBy`가 `None`이 아니면 확인을 기다린다.
     - 완료하면 다음 단계로 간다. 마지막 단계 뒤에는 "안내 완료"다.
   - **기능 명령** — 손·키보드 공통. 명령마다 "어느 단계에 대한 것인지"(단계 번호 + 세대 번호)를 붙인다. 지금 단계와 다른 명령은 버린다(로그). 같은 frame에 손 확인과 진행자 확인이 함께 와도 한 단계만 넘어간다.

     | 명령 | 참가자(패널 poke 버튼) | 진행자(키보드, 자리값) |
     |---|---|---|
     | 확인 | "확인" 버튼 | `Space` |
     | 다음(건너뛰기) | — | `Right` |
     | 이전 | — | `Left` |
     | 시점 전환 | 단계의 이동 버튼(14·15) | `1` 동승석, `2` 2열 |
     | 기준(운전석) 복귀 | "운전석으로 돌아가기" 버튼(기준이 아닐 때만 보임) | `Home` |
     | 처음부터 | — | `F5`(단계 1, 기준 시점, 문 닫힘·잠김) |
     | 정렬 무시하고 시작 | — | `O` |

   - **누가 했는지 구분한다**(AGENTS.md "진행자 대리 조작과 참가자의 독립 수행을 구분").
     - 규칙으로 완료되거나 패널 확인으로 끝나면 참가자.
     - 키보드 확인은 진행자 확인, `Right`는 진행자 건너뛰기다.
     - 시점 전환도 참가자 버튼인지 진행자 키인지 적는다.
   - **안내 패널** — `UWidgetComponent` + Slate(D7). 단계가 시작될 때 참가자 머리 앞(60 cm 앞, 15 cm 아래, 자리값)에 놓고, 그 단계 동안은 그 자리에 고정한다(머리를 따라다니지 않음).
     - 보이는 것: `StepId`, 진행(예: "08 · 4/14"), 문구, 상태("확인을 눌러 주세요", "진행자 확인 대기", "운전석으로 돌아가세요").
     - 패널 아래에 poke 버튼(`AVBoRPokeButton`) 두 개를 둔다. 확인 버튼은 확인할 수 있을 때만 보인다. 행동 버튼(이동·돌아가기)은 그 단계에 행동이 있을 때만 보인다.
     - **참가자 패널에는 참가자 정보만 둔다**(리뷰 R1-2): 진행, 문구, 상태 한 줄, 버튼 이름. "진행자 확인 대기"는 참가자에게 "잠시 기다려 주세요"로 보인다.
       - 진행자 정보(정렬 상태·횟수·기록)는 `LogP3Flow`에 남기고, 화면에는 진행자 키(`F1`)로 켤 때만 보인다. 시작 못 하는 이유는 늘 진행자 블록에 보인다.
     - **확인 잠금 시간:** 단계가 시작된 뒤 0.6 s(자리값) 동안 확인 명령을 버리고 확인 버튼을 숨긴다. 빠른 두 번 누름·늦은 진행자 키가 다음 단계를 넘기지 않게 한다(리뷰 R1-1). 행동 명령과 진행자 다음·이전·처음부터는 잠그지 않는다.
   - **위치 유도:** `MarkerTag` 대상 아래 바닥에 고리를 표시한다. 대상 위에 작은 화살표를 둔다.
   - **기록:** `LogP3Flow`에 남긴다. 파일은 만들지 않는다(AGENTS.md "자동 기록 시스템은 만들지 않는다").
     - 단계 시작·완료(누가, 걸린 시간, 다시 시도·이전·건너뛰기 횟수)
     - 버린 명령(이유)
     - 시점 전환
     - 끝에 요약 한 줄
3. **접근 영역** (`UVBoRApproachZoneComponent`, 차량에 붙임, 태그 `Car.Approach`) — D3.
   - 상자 영역에 참가자 머리 수평 위치가 들어오면 접근이다. 상자 + 30 cm(자리값) 밖으로 나가야 이탈이다(히스테리시스, 경계에서 깜빡이지 않게).
   - 머리 위치는 HMD가 TRACKED일 때만 쓴다(P0-c §3-3처럼 `IsTracking`). 추적이 안 되면 상태를 그대로 둔다.
   - 이벤트 `OnParticipantApproached`·`OnParticipantDeparted`, 함수 `IsParticipantNear()`를 둔다. 안내 흐름이 돌지 않아도 동작한다.

## 3. 지켜야 할 조건 (바꾸면 안 되는 것)

- **정렬은 시작할 때 저장값으로만 적용한다.** 착석·단계 진행·추적 복귀 때 머리 자세로 다시 계산하지 않는다(U-07, P0-c §3-1).
- **한 명령은 한 번만 처리된다.** 손과 키보드가 같은 단계에 동시에 확인해도 한 단계만 넘어간다. 지난 단계에 대한 명령은 버린다(T-04).
- **관찰 단계는 확인으로만 완료된다.** 도착·응시·추적 손실만으로 완료하지 않는다(T-06). `Confirm`·`Viewpoint` 규칙은 확인이 있어야 끝난다. `Seated`는 추적이 끊긴 시간을 세지 않는다.
- **시점 전환은 암전 중 한 번만.** 끝나면 Pawn이 `CalculatePawn(저장값, 대상)`과 정확히 같다(위치 0.1 mm, Yaw 0.01°, 검산용). 기준 복귀도 같다. 전환을 거듭해도 오차가 쌓이지 않는다.
- **하차(18) 전에는 기준 시점이다.** `bRequireBaseViewpoint` 단계는 기준이 아니면 완료되지 않는다.
- **접근 이벤트는 들어올 때 한 번, 나갈 때 한 번이다.** 경계에서 깜빡이지 않는다. 흐름과 무관하게 동작한다.
- **데이터 에셋이 단계의 진실이다.** 단계 순서·문구·규칙을 코드에 다시 적지 않는다(기본값 생성자는 예외).
- P0·P1·P2 코드와 시험은 그대로 동작한다. 원거리·레이 잡기 차단, 던지기 꺼짐도 그대로다. `Config/*.ini` 변경 없음.
