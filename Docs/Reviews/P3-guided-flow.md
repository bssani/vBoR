# P3 리뷰 기록

명세: [Docs/Specs/P3-guided-flow.md](../Specs/P3-guided-flow.md) · 브랜치: `codex/P3-guided-flow`

**Codex가 할 일:**
- 상태가 `열림`인 항목을 위에서부터 반영한다.
- 항목의 세 칸은 이렇게 다룬다:
  - **문제**는 반드시 해결한다.
  - **제안**은 권장이다. 다르게 하면 보고 ③에 이유를 적는다.
  - **확인할 시험**은 새로 넣거나 고칠 자동화 시험이다.
- 같은 브랜치에 새 커밋으로 한다. 반영한 항목의 상태를 `반영함 (<커밋 제목>)`으로 바꿔 같은 커밋에 넣는다. 커밋 본문에 보고 ①~⑤를 쓴다.
- AGENTS.md "일을 키우지 않는다"를 지킨다: 하위 에이전트 없이 혼자, 빌드·전체 시험은 끝에 한 번.
- 판단이 필요하면 맨 아래 "질문"에 적고 멈춘다.
- push·`main` 머지는 하지 않는다. 끝나면 `HANDOFF.md`의 "Codex 결과"를 채운다.

### 1회차에 확인한 것

- **빌드·시험 재현.** 에디터를 닫고, vBoR 소스 수정 시각을 갱신한 뒤 빌드했다.
  - non-unity(`-DisableUnity -Module=vBoR`): `.cpp` 39개와 gen 파일을 하나씩 컴파일했다. 경고·오류 0.
  - unity: 경고·오류 0.
  - 시험: `vBoR.*` **91/91 Success**(기존 79 + P3 12), `TEST COMPLETE. EXIT CODE: 0`. 로그: `Saved/Logs/P3R1ClaudeAutomation.log`. 추가 Warning 없음.
- **사용자 요청 1 — 밖에서 시작해 앉으면 맞음(D2):** `UVBoRVehicleAlignmentComponent`가 BeginPlay에서 `BuckEye.json`을 읽어 운전석 eye로 Pawn을 놓는다(`VBoRVehicleAlignmentComponent.cpp` `InitializeAlignment`).
  - 참가자 머리 자세는 읽지 않는다. 착석 때 다시 계산하지 않는다.
  - 재중심이면 "확인 필요"이고 Pawn은 그대로다.
  - 매 frame 추적 원점·플레이 영역을 다시 본다.
- **사용자 요청 2 — 접근 신호(D3):** `UVBoRApproachZoneComponent`.
  - TRACKED 머리의 수평 위치로 판정한다. 들어오는 즉시 접근, 30 cm 더 나가야 이탈이다.
  - `OnParticipantApproached`·`OnParticipantDeparted`, `IsParticipantNear()`를 둔다.
  - 진행기와 무관하게 컴포넌트 Tick에서 동작한다.
  - 기본 영역은 차체 + 150 cm(`P3VehicleMock.cpp:42`)다.
- **사용자 요청 3 — 데이터 에셋(D1):** `UVBoRScenarioAsset::Steps`.
  - 필드: StepId·문구·규칙·태그·문 각도·착석 시간·확인 주체·기준 시점·표시 태그. 한국어 툴팁이 있다.
  - 기본 14단계가 명세 표와 같다.
  - 시작 전 검사: 태그가 하나만 맞는지, 종류가 맞는지, StepId가 01–16·18–20 두 자리인지 본다. 실패하면 시작하지 않고 목록을 보인다.
- **명령(T-04):** 입력이 들어온 frame의 (단계 번호, 세대)를 붙여 큐에 넣는다. 처리할 때 지금 단계와 다르면 버린다. 한 frame에 규칙으로 여러 단계를 넘기지 않는다. 같은 frame의 손 확인 + 진행자 확인은 한 번만 넘어간다(E1).
- **관찰은 확인으로만(T-06):** `Confirm`·`Viewpoint` 규칙은 늘 확인이 필요하다(`NeedsConfirmation`). 좌석 체류는 추적이 끊긴 시간과 복구 frame을 세지 않는다(`VBoRParticipantZones.cpp:64-74`).
- **시점(T-05):**
  - 전환 중 요청은 버린다.
  - 암전 뒤 매번 `CalculatePawn(저장값, 대상 eye)`를 직접 계산하므로 오차가 쌓이지 않는다.
  - 18번은 기준이 아니면 완료도, 진행자 건너뛰기도 막힌다(`VBoRScenarioRunner.cpp:186, 314-315`).

- **버튼은 실제 경로:** 패널 확인·행동 버튼과 먼 버튼 모두 P0-b `OnButtonPressed`(ISDK poke)로 받는다. 숨긴 버튼은 poke도 끈다. P2 R1-3 교훈(이벤트를 직접 넣는 시험만으로는 부족)을 지켰다.
- **근사 차량·레벨·에셋:** `L_P3_Flow.umap`·`DA_P3_Scenario.uasset`을 커밋했다.
  - 레벨: 판 차체, 접근 영역, 시작 표시(`Saved/Logs/P3-work/P3Flow-editor-overview.png`).
  - 문: yaw +180, 경첩은 앞, 바깥은 −Y. 좌석 영역은 eye 아래 40·위 25 cm.
  - 모듈 의존 `UMG`·`Slate`·`SlateCore`를 private로 추가했다(패널).
- **토큰:** 새 대화 한 세션(00:31–01:07), **9.96M**, 하위 에이전트 0.
  - 빌드는 non-unity·unity 각 3번, 시험 4번이다. 시험 실패(버튼 방향) 수정과 마지막 표시 추가 때문이다.
  - 지금까지 가장 큰 기능이다.
- **알아 둘 것(항목 아님):** `DA_P3_Scenario.uasset`(1,241 바이트)에는 단계가 저장돼 있지 않다.
  - UE는 클래스 기본값과 다른 값만 저장한다. 그래서 손대지 않은 에셋의 내용은 C++ 생성자 기본값이다. 사용자가 한 번 고치면 배열 전체가 에셋에 저장된다.
  - **따라서 앞으로 생성자 기본 단계를 바꾸지 않는다.** 바꾸면 아직 손대지 않은 에셋도 같이 바뀐다. 새 흐름은 에셋에서 고친다.
- **알아 둘 것:** 정렬을 무시하고 시작(`O`)하면 시점 전환(14·15)과 `F5`는 동작하지 않는다(저장 정렬 필요). 진행자 건너뛰기로 넘어간다. 로그에 남는다.

## 열린 항목

### R1-1 확인 명령이 단계 시작 직후에도 받아져, 빠른 두 번 누름이나 늦은 진행자 키가 다음 단계를 넘긴다 (Claude 명세 빈틈) — 반영함 (`353d502`)

**문제**
- **위치:**
  - `Source/vBoR/Interaction/VBoRScenarioRunner.cpp:239-247`(`FreezeLiveToken`·`QueueLive`): 입력이 들어온 frame의 토큰을 쓴다. 한 frame만 지나도 새 단계의 토큰이 붙는다.
  - `:305-311`(`Confirm`): 확인을 받는다.
  - `:394`: 확인 버튼은 새 단계에서 확인할 수 있게 되는 즉시 다시 보인다.
- **발생 조건:**
  - 참가자가 "확인"을 빠르게 두 번 누름(두 번째는 100–300 ms 뒤).
  - 진행자가 규칙으로 막 끝난 단계에 `Space`를 늦게 누름. 예: 01 접근으로 자동 완료된 직후 → 02(외장 조명 관찰, Either)가 바로 진행자 확인으로 끝난다.
  - 확인 단계가 이어지면 그대로 넘어간다. 예: 14 확인 → 15는 시점이 달라 막힘. 반면 12 → 13은 13이 버튼이라 막힘. 사용자가 확인 단계를 연달아 넣으면 그대로 넘어간다.
- **영향:** 참가자가 보지도 않은 관찰 단계가 완료로 기록된다(T-06). 진행자 확인이 그 단계의 확인으로 잘못 남는다(T-04).
  - 지금 시험(E1·E2)은 같은 frame만 확인한다.
- **원인:** 명세 E2를 Claude가 "frame 직후"로 써서 시간 폭을 정하지 않았다. 명세를 고쳤다(1회차 개정, §2-2·§4 E2).

**제안**
- 단계가 시작된 뒤 **확인 잠금 시간**(0.6 s, 자리값, 프로퍼티) 동안 받은 `Confirm`은 버린다. 이유는 "단계 시작 직후"다. 참가자·진행자 모두에 적용한다.
- 같은 시간 동안 패널 확인 버튼을 숨긴다.
- 시점 전환·기준 복귀 같은 행동 명령과 진행자 `Next`·`Previous`·`F5`·`O`는 잠그지 않는다. 진행자는 "다음"으로 넘길 수 있다.

**확인할 시험**
- 단계 A를 확인으로 끝낸 뒤 0.3 s 안에 다시 확인 → 단계 B는 끝나지 않고 "단계 시작 직후"로 버린다. 0.7 s 뒤 확인 → B가 끝난다.
- 01이 규칙으로 끝난 직후(0.1 s) 진행자 `Space` → 02가 끝나지 않는다.
- 잠금 시간 동안 확인 버튼이 숨겨지고 poke도 꺼진다.
- `Next`는 잠금 시간에도 동작한다.

### R1-2 참가자 안내 패널에 진행자·디버그 정보가 섞여 있다 (Claude 명세 빈틈) — 반영함 (`353d502`)

**문제**
- **위치:** `Source/vBoR/Interaction/VBoRScenarioRunner.cpp:363-389`(`GetPanelText`). 참가자 패널 하나에 다 나온다:
  - "근사 형상·자리값"
  - 정렬 상태 문자열과 정렬 무시 여부
  - "이전·재시도·건너뛰기·버림 단계/권한/규칙/전환" 횟수
  - 마지막 시점 명령·마지막 완료 기록
  - 접근·이탈 시각, 좌석 체류·보류 횟수
- **발생 조건:** 늘 그렇다.
- **영향:**
  - 참가자는 안내 문구 아래로 숫자와 진행자용 문장을 같이 본다. 문구를 읽기 어렵다.
  - P3에서 보려는 "한국어 안내가 읽기 쉬운지"(§7)와 나중의 초보자 이해도(T-09)를 흐린다.
  - 진행자 판단 정보("진행자 확인 대기", 정렬 무시)를 참가자가 본다.
- **원인:** 명세 §2 측정 표를 "패널 + `LogP3Flow`"로 써서 참가자 패널과 진행자 정보를 나누지 않았다(Claude). 명세를 고쳤다(1회차 개정, §2-2·측정 표).

**제안**
- **참가자 패널**에는 이것만 둔다:
  - 진행(예: "08 · 4/14")
  - 안내 문구
  - 참가자에게 필요한 상태 한 줄("확인을 눌러 주세요", "운전석으로 돌아가세요", "잠시 기다려 주세요")
  - 버튼 이름
- "진행자 확인 대기"는 참가자에게 "잠시 기다려 주세요"로 보인다.
- **진행자 정보**는 늘 `LogP3Flow`에 남긴다.
  - 화면에는 진행자 키(`F1`, 자리값)로 켤 때만 패널 아래에 따로 보인다. 기본은 끔이다.
  - 정렬 필요·태그 검사 실패처럼 흐름을 시작하지 못하는 이유는 진행자 정보가 꺼져 있어도 보인다. 참가자에게는 "준비 중입니다"로 보인다.
- "근사 형상·자리값" 표시는 근사 차량 라벨(`P3VehicleMock`의 `MockLabel`)에 둔다(AGENTS.md "화면에 근사 형상임을 드러낸다").

**확인할 시험**
- 진행자 정보가 꺼져 있을 때 패널 텍스트에 "버림"·"건너뛰기"·"정렬"·"generation"이 없고, 안내 문구가 있다.
