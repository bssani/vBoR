## 질문

### Q1 — D4의 바깥쪽 여유와 E7의 회전각 비교가 반대

- **상태:** 열림 (2026-11-01, Codex). Claude 명세 개정 대기. 리뷰 회차가 아니라 구현 전 질문만 기록한다.
- **문제:** `Docs/Specs/R8a-axis-push-face.md:20` D4는 깊이 판정과 회전각 계산 모두 면을 바깥쪽으로 0.8 cm 옮기도록 요구한다. 같은 명세 `:67` E7은 이때 회전각이 0 cm보다 **덜** 돌아가야 한다고 요구한다. 동일한 손 위치에서 관절 중심을 바깥쪽 면에 유지하려면 회전은 오히려 더 커져 두 조건을 동시에 만족할 수 없다.
- **수치 예제:** 회전축 +X, Radial +Y, Normal +Z, 원래 바깥 면 Z=-1 cm, 반대 면 Z=+1 cm, 손 관절 위치 `(0,15,-0.5)` cm. Face 0을 아래에서 미는 경우다. 현재 `Source/vBoR/Interaction/VBoRAxisPart.cpp:450-457`은 `Target=atan2(N,R)-asin(Plane/Radius)`로 각을 구하고 Face 0의 양의 회전만 허용한다. `Radius=sqrt(15^2+0.5^2)` cm이다.
  - 여유 0: `Plane=-1` → **1.911276°**.
  - D4의 바깥쪽 여유 0.8: `Plane=-1.8` → **4.979106°**.
  - 이때 관절은 회전된 판 좌표에서 각각 Z=-1 / -1.8 cm가 되어 D4의 접촉 거리와 맞지만, E7의 “덜 돌아감”과는 반대다. Face 1도 부호만 반대이며 회전량의 절댓값이 커진다.
- **질문:** D4의 바깥쪽 이동과 관절 중심의 0.8 cm 거리 유지를 기준으로, E7의 비교를 “같은 판정점에서는 0일 때보다 회전량의 절댓값이 커짐”으로 개정할지 확인이 필요하다. E7이 다른 손 이동 비교를 뜻한다면 비교할 초기 자세·손 위치·이동량을 명세에 적어 달라. 구현자가 부호나 시험 기대값을 임의로 선택하지 않는다.
- **제안:** D4의 의도가 손가락 살 두께 보정이라면 D4를 유지하고 E7의 비교 문구를 고친다. 위 예제의 각도 식은 기존 제품 코드에서 확인했으며, 새로운 엔진·플러그인 API 조사는 필요하지 않았다.
- **확인할 시험:** E6의 면 앞 0.5/1.0 cm 시작 여부, E7의 동일 손 위치에 대한 0/0.8 cm 각도(0.1°)와 회전된 판 좌표의 접촉 거리, E8의 0 cm 기존 동작, E9의 양쪽 면 부호·거리. 합의 전 기대값을 확정하지 않는다.
