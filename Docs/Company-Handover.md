# 회사 PC → Claude 넘겨주기 — 무엇을, 어떤 형식으로

> 읽는 사람: 회사 PC에서 실제 차 데이터로 작업하는 사람과 그 PC의 AI.
> 언제 쓰나: 회사 PC에서 값을 뽑거나 BP를 만들거나 시험한 뒤, Claude(이 리포의 명세·리뷰 담당)에게 다음 작업을 맡길 때.
> 같이 볼 것: [Company-PC-Guide.md](Company-PC-Guide.md) §4(뽑을 값 목록), [Blueprint-Guide.md](Blueprint-Guide.md)(BP 만드는 법).

## 0. 어디에 적어 넘기나 — 보안 먼저

- **차량 수치, CAD 파일, 실물 사진은 리포에 올리지 않는다.** 올려도 되는지 아직 정하지 않았다(Company-PC-Guide §5).
- 적는 곳은 **`Saved/Handover/<날짜>.md`**다. `Saved/`는 git이 무시한다(`.gitignore:68`). 넘기는 방법은 둘이다.
  - Claude Code가 그 PC에서 돈다면: "Saved/Handover/2026-10-27.md 읽어"라고만 하면 된다.
  - 다른 PC의 Claude라면: 그 파일 내용을 대화에 붙여 넣는다.
- **리포에 올려도 되는 것:** 수치가 없는 내용이다. 문제 보고, 시험 결과(통과·실패), BP 경로·부모 클래스·태그, 로그에서 수치를 뺀 줄.
- 회사 이름, 프로그램 이름, 일정, 회의 내용은 어디에도 적지 않는다(AGENTS.md).

## 1. 맨 위에 늘 적을 것 (5줄)

```
날짜: 2026-10-27
PC: 회사 PC (GPU 이름)
git: <git log -1 --format='%h %s' 결과> / 바뀐 파일: <git status --short 결과>
에디터: 닫음 / 열림, UE·플러그인 버전 바꿈: 아니오
이번에 한 것: (한두 줄)
```

- 커밋 해시가 있어야 Claude가 같은 코드를 보고 말할 수 있다.
- 커밋하지 않은 파일(특히 `.uasset`·`.umap`)이 있으면 꼭 적는다. Claude는 그 PC의 에디터 상태를 볼 수 없다.

## 2. 가장 먼저 넘길 것 — 이것만 있으면 정렬과 차 기준점을 시작할 수 있다

| 순서 | 무엇 | 왜 먼저 |
|---|---|---|
| 1 | **좌표계**: CAD 원점, 축 방향(X가 앞인지 뒤인지), 단위, 설계 하중 상태의 지면 높이 | 모든 값의 변환이 여기서 갈린다 |
| 2 | **정렬 점 4개**: 순서, 이름, CAD 좌표, 좌석 조절에 따라 움직이는지, 위에서 짚을 수 있는지 | 4점 정렬(U-18, P4h) |
| 3 | **SgRP 셋**(운전석·동승석·2열 — 2열은 어느 좌석인지) + **SgRP를 정한 좌석 상태**(슬라이드·등받이 각·높이) | 좌석 전환(14·15), 실물 좌석 맞추기 |
| 4 | **실물 Buck**: 아래 §3 | 정렬 결과를 판단하려면 실물 쪽 사실이 필요하다 |
| 5 | **차체 크기·바닥 윤곽** | `Car.Footprint`, 바닥 경로 |

나머지 부품 값(Company-PC-Guide §4 #6–#16)은 그 부품 BP를 만들 때 하나씩 넘겨도 된다.

## 3. 실물 Buck — Claude가 CAD에서 알 수 없는 것

| 항목 | 적을 것 |
|---|---|
| 좌석 | 실제 차 좌석인지, 레일이 붙어 있는지, 어디에 고정했는지(받침대 높이) |
| 좌석 높이 | **실제 바닥에서 잰 높이**(예: 바닥 → 레일 윗면, 바닥 → 방석 앞 끝). 줄자 값과 잰 자리 |
| 좌석 상태 | 지금 슬라이드·등받이·높이 조절 위치. SgRP 기준 상태와 같은지 |
| 정렬 점 4개 | 실물에서 어디인지 말로(사진은 리포 밖). 손이 닿는지, 단단한지 |
| 방 | 플레이 영역 크기(가디언), 좌석이 영역 안 어디에 있는지, 차 앞뒤로 걸을 수 있는 거리 |
| 장비 | Link 방식(유선·Air Link), 주사율, 손 추적 설정, TV 연결 |

## 4. 값 적는 형식

**규칙:**
- **CAD 원본과 UE 변환을 둘 다 적는다.** UE는 cm, X 앞, Y 오른쪽, Z 위, 차 원점 기준이다.
- **변환 식은 한 번만 맨 위에 적는다.** 예: `UE = (−X_cad, +Y_cad, Z_cad − 지면) / 10`.
- **축은 두 점으로 적는다**(경첩의 위 점·아래 점). 방향을 말로 적으면 부호를 틀리기 쉽다.
- **각도는 deg와 방향으로 적는다.** 예: "닫힘 0에서 바깥으로 70°".
- 값마다 출처(CAD 어느 조립품·측정)를 적는다. 모르면 "추정"이라고 쓴다.

```
## 좌표계
CAD 원점: (설명) / 축: X=뒤, Y=오른쪽, Z=위 / 단위: mm / 지면 Z_cad = −350 mm
변환: UE_cm = (−X, Y, Z+350)/10

## 정렬 점
| Order | 이름(Label) | CAD (mm) | UE (cm) | 좌석 조절로 움직임 | 위에서 짚기 | 출처 |
| 1 | Front-left rail end | (…) | (…) | 아니오 | 예 | 시트 레일 조립품 |

## SgRP
| 좌석 | CAD (mm) | UE (cm) | 좌석 상태(슬라이드·등받이) | 출처 |
| 운전석 | … | … | 최후방, 등받이 25° | … |

## 부품 축 (예: 운전석 문)
| 부품 | 축 위 점 CAD | 축 아래 점 CAD | 열림 방향·최대 각 | 같이 움직이는 메시 | 출처 |
```

## 5. 에디터에서 만든 것 (BP·레벨)

Claude는 다른 PC의 에디터를 볼 수 없다. 만들거나 바꾼 BP마다 적는다.

| 적을 것 | 예 |
|---|---|
| 경로·부모 클래스 | `/Game/Main/Car/Parts/BP_Door_FL` ← `AVBoRHingedDoor` |
| 태그 | `Car.DriverDoor` |
| 기본값에서 바꾼 값만 | `MaxAngleDeg 68`, `bUsePushFaceBox 켬`, `HingePivot` 위치·회전 |
| 레벨의 붙임 관계 | `BP_DoorHandle_FL_Ext` → `BP_Door_FL` 밑(Outliner) |
| 검사 결과 | "설정 검사" 출력 줄, Play 때 `Template Mismatch`·`P2e setup:`·`시작 차단:` 줄 |

- Claude Code가 그 PC에서 돌고 에디터 MCP가 연결돼 있으면, 레벨 경로만 주고 "MCP로 읽어"라고 하면 된다. Claude는 읽기만 한다.

## 6. 문제가 생겼을 때 — 한 문제에 한 덩어리

```
### 문제: (한 줄 — 예: 기어 끝 버튼이 레버를 따라오지 않음)
- 부품·BP: /Game/Main/Car/Parts/BP_GearLever (부모 AVBoRAxisPart), 버튼은 Child Actor로 AxisPivot 밑
- 한 일: 1) L_Main Play 2) 기어를 위로 밈
- 기대: 버튼이 레버 끝에 붙어 같이 움직임 / 실제: 버튼이 제자리
- 얼마나 자주: 매번 / 가끔(10번 중 n번)
- 로그: Saved/Logs/vBoR.log에서 그 시각 앞뒤 20줄(수치는 빼도 됨)
- 진행자 창: LastCommand·Alignment·Point alignment 줄 그대로
- 화면: 스크린샷·영상 경로(리포 밖)
- 커밋: <해시>
```

- **실제로 본 것과 추측을 나눠 적는다.** "버튼이 안 따라옴"(본 것)과 "Child Actor 붙임 문제 같음"(추측)을 다른 줄에 쓴다.
- VR에서만 생기는 문제는 PIE(VR 없이)에서도 나는지 같이 적는다.

## 8. 성능 — 회사 PC에서만

- 이 집 PC의 fps는 장비 한계라 보지 않는다. **회사 PC 값이 기준이다.**
- 적을 것: GPU·CPU, Link 주사율·해상도, `stat unit`의 Frame·Game·Draw·GPU ms.
- 재는 자리는 L_Main의 세 곳이다: 차 앞 시작 위치, 운전석, 2열 시점.
- 합격 기준은 Claude가 정하지 않는다(평가 담당자와 합의할 값).
